# alyze-cjk

CJK (Chinese, Japanese, Korean) text analysis for [`alyze`](../), enabled through its `cjk`
feature and re-exported as `alyze::cjk`. Kept as a separate crate so the dictionaries (`data/`,
about 4.7 MB) don't inflate `alyze` for users who don't need them.

Provides:

- `smartcn`: a port of Apache Lucene's `smartcn` analyzer, the Hidden Markov Model word segmenter
  for Simplified Chinese behind Elasticsearch's `smartcn` analyzer and `smartcn_tokenizer`. The
  tokenizer stage reproduces Lucene's output exactly (checked against golden files generated by
  Lucene itself, see `testdata/smartcn/README.md`); the analyzer stage stems English with Porter2
  where Lucene uses Porter.
- `nori` (in progress): a port of Lucene's `nori` analyzer, the MeCab-style Korean morphological
  analyzer behind Elasticsearch's `nori` analyzer, `nori_tokenizer`, `nori_part_of_speech`,
  `nori_readingform` and `nori_number`, with mecab-ko-dic as its dictionary. Checked token for
  token against Lucene (see `testdata/nori/README.md`); the only intended differences are how a
  surrogate pair split by Lucene's 1024-unit unknown-word cap is reported and the lowercase
  mapping the analyzer ends with.
- `kuromoji` (in progress, test suite first): a port of Lucene's `kuromoji` analyzer, the
  MeCab-style Japanese morphological analyzer behind Elasticsearch's `kuromoji` and
  `kuromoji_completion` analyzers, `kuromoji_tokenizer` and the `kuromoji_*`, `ja_stop`,
  `hiragana_uppercase` and `katakana_uppercase` filters, with mecab-ipadic as its dictionary.
  Checked token for token against Lucene (see `testdata/kuromoji/README.md`), with the same
  intended differences as `nori`.
