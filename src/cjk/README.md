# CJK analysis

CJK (Chinese, Japanese, Korean) text analysis is part of `alyze`, under `alyze::cjk`.
Enable `smartcn`, `nori`, or `kuromoji` individually, or `cjk` for all three.
All are disabled by default. Only enabled analyzers and their dictionaries are compiled.

Provides:

- `smartcn`: a port of Apache Lucene's `smartcn` analyzer, the Hidden Markov Model word segmenter
  for Simplified Chinese behind Elasticsearch's `smartcn` analyzer and `smartcn_tokenizer`. The
  tokenizer stage reproduces Lucene's output exactly (checked against golden files generated by
  Lucene itself, see `testdata/smartcn/README.md`); the analyzer stage stems English with Porter2
  where Lucene uses Porter.
- `nori`: a port of Lucene's `nori` analyzer, the MeCab-style Korean morphological
  analyzer behind Elasticsearch's `nori` analyzer, `nori_tokenizer`, `nori_part_of_speech`,
  `nori_readingform` and `nori_number`, with mecab-ko-dic as its dictionary. Checked token for
  token against Lucene (see `testdata/nori/README.md`); the only intended difference is how a
  surrogate pair split by Lucene's 1024-unit unknown-word cap is reported.
- `kuromoji`: a port of Lucene's `kuromoji` analyzer, the
  MeCab-style Japanese morphological analyzer behind Elasticsearch's `kuromoji` and
  `kuromoji_completion` analyzers, `kuromoji_tokenizer` and the `kuromoji_*`, `ja_stop`,
  `hiragana_uppercase` and `katakana_uppercase` filters, with mecab-ipadic as its dictionary.
  Checked token for token against Lucene (see `testdata/kuromoji/README.md`), with the same
  intended differences as `nori`.

## Dictionary builds

Published packages download the enabled languages' precompiled dictionaries from the
`dictionaries-v1` GitHub release, verify their pinned SHA-256 checksums, and extract them into
Cargo's build directory. The dictionaries are embedded in the executable; runtime needs no
network access or dictionary files. Downloaded archives are reused until the build directory
is cleaned. Dictionary updates require a new release tag and checksums in `build.rs`.

For offline builds, download the release archives in advance and set
`ALYZE_CJK_DICTIONARIES` to their directory (prefer an absolute path). The directory must
contain `smartcn.tar.gz`, `nori.tar.gz`, and/or `kuromoji.tar.gz` for the enabled features.
These archives undergo the same checksum verification as downloads. A missing or incorrect
local archive fails the build without falling back to the network. `cargo vendor` does not
include these assets, and Cargo's `--offline` flag alone does not disable build-script downloads.

Repository builds use the checked-in `data/` files unless `ALYZE_CJK_DICTIONARIES` is set.
Create release archives with `python3 scripts/package-dictionaries.py` from the
repository root; they are written to `target/dictionaries/`. Publish those exact archives
under the release tag in `build.rs` before publishing this crate, and keep published assets
unchanged. `data/NOTICE` preserves the notice included in the published v1 archives,
so regenerating them keeps their pinned checksums. The archives include the dictionary licenses and notices.

On docs.rs, the build script creates empty placeholders so documentation can build without
network access. Those placeholders are only for documentation and cannot tokenize text.
